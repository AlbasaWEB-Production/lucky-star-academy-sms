# Prompt: Redesign the Lucky Star Academy SMS user interface

Paste everything below this line into the agent, from inside the repo root (`lucky-star-academy-sms/`).

---

## THE JOB

Redesign the user interface of the Next.js 16 / React 19 / MUI 9 application in `web/` so that it looks like a product a working designer made for one specific school, not a template an AI assembled from a reference site. The scope is every surface a user sees: the landing page (`src/app/page.tsx`), the auth pages and `AuthShell`, the signed-in `AppShell` (top bar, sidebar, account menu), the three role dashboards, the list pages built on `TableShell`, the detail pages, the forms, and the empty states. The theme in `src/theme.ts` and the shared components in `src/components/ui/*` are where most of the work belongs; page-level edits should be the consequence of decisions made there, not one-off tweaks.

Work in this order and do not skip the first two steps. First, audit: run the app, open every route as each role, and write down what currently gives it away as machine-made. Some of it is already visible in the code: the font stack is the OS default with no chosen typeface; every icon sits in an identical 48px green circle whether it is on a stat card, a role card or a form; the admin dashboard is six identical tiles in a uniform grid; `StatCard` accents are hardcoded hex values left over from the old purple theme (`#080a43`, `#270843`) that no longer belong to any palette; the top bar carries a search field that is not wired to anything; the landing nav links to `#features` and `#about` anchors that do not exist; the "Lucky Star for…" segmented chips and the blurred `Orb` are lifted from the SchoolAI reference; and `PAGE-CONVENTIONS.md` still documents the purple `#7f56da` palette the theme abandoned. Find the rest. Second, decide: write a short design note (`web/DESIGN.md`) with five to eight named decisions — typeface pairing and type scale, spacing rhythm, the colour story and exactly where gold appears, corner radius system, card and table treatment, how density differs between the admin tables and the student portal, and the landing page concept. Post that note and stop for a go-ahead before editing components. Third, implement: theme and shared components first, then a pass over each surface, verifying in the browser at desktop and at 360px width as you go.

## THE WHY

This is a real system for Lucky Star Academy in Yendi, Northern Region, Ghana, a Primary 1–6 school. The people using it are a school administrator, teachers entering attendance and marks, and pupils or their parents checking results on phones. It is also an ALBASA WEB client deliverable, and the client will judge the whole system by how it looks before they judge how it works. A UI that reads as a borrowed template undermines trust in the data behind it and undercuts what the work is worth. The current design already did the hard part of moving off the tutorial-era purple MUI look toward something calm and legible; what remains is the difference between "clean because it copied something clean" and "clean because someone made choices for this school". That difference is the entire job.

## THE GUARDRAILS

Read `web/PAGE-CONVENTIONS.md` and `web/AGENTS.md` before writing any code, and follow the Next.js 16 docs under `node_modules/next/dist/docs/` rather than your memory of older versions. Do not touch the data layer, server actions, auth, RLS, routing or any file under `src/lib/**` or `supabase/**`; this is a presentation change only, and every feature and every piece of information currently on a page must still be there when you finish. Server pages stay server components and fetch as they do now; interactivity stays in `"use client"` components; never pass a function from a server component to a client component; do not use MUI `Grid`. `npm run typecheck` must pass after every commit, and do not run `npm run build` while a dev server is running.

Keep the school's identity: green is the single working colour, gold is an accent that never appears as text on white, and `secondary.main` stays dark enough to serve as ink. Express colour through theme tokens; the only place a raw hex is acceptable is inside a chart series. You may add exactly one new dependency class — a typeface loaded through `next/font` — and nothing else: no Tailwind, no second component library, no animation library, no icon set beyond `@mui/icons-material`. Use the school's own assets (the logo in `SchoolLogo`, the photographs in `StudentPhotoCollage`); do not add stock photography, invented testimonials, fake statistics or placeholder copy, and do not leave placeholder UI in place — remove the unwired search box rather than leaving a decorative one, and remove nav links whose targets do not exist rather than inventing sections to satisfy them. One earlier decision for the landing page stands until the owner says otherwise: the hero background should be a soft brand gradient with subtle school motifs, treated as a full-screen 16:9 hero; if your concept conflicts with that, say so in the design note rather than silently changing it.

Meet WCAG 2.1 AA: 4.5:1 contrast for body text, visible keyboard focus on every interactive element, tap targets of at least 44px on mobile, no information carried by colour alone. Everything must work at 360px wide with no horizontal scroll. Do not add dark mode, page transitions or decorative motion; restraint is part of the brief. Do not reskin the app to resemble Notion, Linear, SchoolAI or any other named product. Commit in small, logically separate commits (theme, then shared components, then one commit per surface) so any step can be reverted alone, and update `PAGE-CONVENTIONS.md` so it describes the palette and components that actually exist when you are done.

## DONE MEANS

The definition of done is that the UI looks professional, modern and not machine-made: a designer looking at it would believe a person made deliberate choices for this school. Concretely, every one of the following holds.

A chosen typeface pairing is loaded through `next/font` and applied through the theme with an intentional scale — display, heading, body, caption — so headings, labels, table text and numbers are visibly different jobs, not MUI defaults at different sizes. A single spacing rhythm and a small, purposeful set of corner radii are used everywhere, and not every element shares the same radius. Green does the work and gold appears in a handful of deliberate places you can list, with warm neutrals in between; no hex value outside a chart series is off-palette.

Components differ by purpose. A metric tile, a list card, a role card and a notice card are not the same rectangle with different words in it; the identical icon-in-a-circle motif is gone; the `Orb` and the borrowed segmented chips are gone; dashboards have hierarchy — something is primary, something is secondary — instead of a uniform grid. Tables read as data with clear column alignment, sensible density and row affordances, not as a banner with rows under it. Forms group related fields, use realistic widths, show helper text and errors inline, and have one obvious primary action. Every empty state says specifically what is missing and offers one clear next step in plain language a teacher in Yendi would use.

The landing page tells this school's story in its own words — Lucky Star Academy, Yendi, Primary 1–6 — with its own logo and photographs, no dead links, no borrowed patterns, and a hero that honours the gradient-with-school-motifs decision or a documented, approved alternative. The auth pages, the shell and the portals feel like one product on desktop and on a phone.

Every route renders for every role with no console errors or hydration warnings; `npm run typecheck` passes; an axe or Lighthouse accessibility check reports no critical issues and Lighthouse accessibility scores 95 or above on the landing, login and admin dashboard pages; nothing scrolls horizontally at 360px. `web/DESIGN.md` records the decisions and `web/PAGE-CONVENTIONS.md` matches the code. Before-and-after screenshots of the landing page, a login page, the admin dashboard, a table page and a form page, at desktop and at 360px, are saved to `Claude outputs/ui-redesign/`, and the final message summarises the decisions made, anything deliberately left alone, and anything that still needs the owner's judgement.
